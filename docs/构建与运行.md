# 安装、构建与运行

## 下载与安装

普通使用可直接下载 [Wumi-1.1.1-arm64.dmg](https://github.com/kbwumin13-sudo/Wumi/releases/download/v1.1.1/Wumi-1.1.1-arm64.dmg)，无需安装 Xcode。此包适用于 **macOS 15+、Apple Silicon（arm64）**，不提供 Intel 安装包。后续版本见 [最新 Release](https://github.com/kbwumin13-sudo/Wumi/releases/latest)。

1. 打开 DMG，将 `Wumi.app` 拖到 `Applications`（应用程序）。
2. 从「应用程序」打开 Wumi。
3. 首次若被 Gatekeeper 拦截，打开「系统设置 → 隐私与安全性」，在此次拦截的提示处选择「仍要打开」，按系统提示确认后打开。

公开 DMG 仅使用 **ad-hoc 签名**，没有 Developer ID 签名，也未经 Apple 公证。首次访问受保护目录时按系统提示授权；需要完全磁盘访问时，可在应用「设置 → 隐私与权限」查看引导。这些目录访问权限与首次打开时的 Gatekeeper 提示分别处理。

发布内容、已知限制与 SHA-256 校验方法见 [1.1.1 发布说明](releases/v1.1.1.md)。

首次打开被拦截时的系统操作见 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

## 源码开发环境

目标平台 macOS 15+，包清单要求 Swift tools 6.2+，需要包含对应 macOS SDK 的 Xcode 工具链。既有开发环境：macOS 27、Xcode 27 / Swift 6.4、Apple Silicon。

```sh
git clone https://github.com/kbwumin13-sudo/Wumi.git
cd Wumi
```

## 构建

```sh
scripts/build-app.sh            # 默认 release、版本 1.1.1，输出 build/Wumi.app
scripts/build-app.sh debug      # 调试构建
scripts/build-app.sh release    # release 构建
SIGN_IDENTITY="证书名" scripts/build-app.sh release   # 指定签名证书
```

脚本流程：`swift build` → 组装 `.app`（Info.plist、`Resources/*.lproj` 字符串表、图标）→ 用 `vtool` 把二进制记录的 SDK 版本改为实际 SDK（SwiftPM 会把它记成部署目标 15.0，macOS 26 起会因此用旧版控件样式绘制窗口）→ `codesign`。图标由 `scripts/make_icon.swift` 原创绘制并用 `iconutil` 生成。

Wumi 的默认版本为 `1.1.1`；仍用 `DIRDESK_VERSION`、`DIRDESK_BUILD` 覆盖版本和构建号。打包只重建 `build/Wumi.app`，不删除或改名旧的 `build/DirDesk.app`，也不清理其他构建产物。图标转换使用本次创建的临时目录。旧包应由主任务在退出旧进程后处理，避免同时注册两个相同 Bundle ID 的应用。

兼容性标识继续使用原值：Bundle ID `com.kbwumin13.dirdesk`、可执行文件 `Contents/MacOS/DirDesk`、模块 `DirDesk`、服务 selector `openInDirDesk`、偏好键、数据路径和 UTI。服务显示名称为“Open in Wumi”，`NSPortName` 与应用名 `Wumi` 一致；不要把它误设为内部可执行文件名。服务实际注册与调用需在新包构建后验证。

### DMG 打包

```sh
scripts/build-app.sh release
scripts/package-dmg.sh
# 或从指定 App 打包到指定目录
scripts/package-dmg.sh /path/to/Wumi.app build/releases
```

打包脚本根据 App 的版本和架构命名附件，默认生成 `build/releases/Wumi-1.1.1-arm64.dmg` 与 `.dmg.sha256` 校验文件。磁盘映像包含 App、指向「应用程序」的安装入口和安装说明，创建后执行完整性校验。脚本只对暂存副本使用 ad-hoc 签名，保留原本地 App 的签名；当前未配置 Developer ID 签名与 Apple 公证。

### 签名身份

没有设置 `SIGN_IDENTITY` 时，脚本优先用登录钥匙串里的本地自签名证书"DirDesk Local Signing"，找不到才用 ad-hoc 签名，最后一行会打印实际用的身份。

```sh
scripts/make-signing-cert.sh    # 一次性：生成"DirDesk Local Signing"代码签名证书并导入登录钥匙串（已存在则跳过）
```

用固定证书签名后，App 的指定要求绑定在证书上，完全磁盘访问等隐私授权在重建后继续有效；ad-hoc 签名每次重建都会变，系统会重新询问。首次用证书签名时，钥匙串会询问 codesign 能否使用该私钥，选"始终允许"后不再询问。此自签名证书只用于本机构建，不是 Developer ID，不能用于 Apple 公证；本次公开 DMG 使用 ad-hoc 签名。

## 运行

```sh
open build/Wumi.app          # 前台启动
open -g build/Wumi.app       # 后台启动，不抢焦点
```

首次访问桌面、文稿、下载会触发系统权限询问；需要免打扰时在「设置 › 隐私与权限」按引导开启完全磁盘访问。用本地证书签名时授权只需给一次；换成 ad-hoc 签名或换证书后需要重新授权。

## 离屏截图（锁屏时也可用）

```sh
open -g -a build/Wumi.app --args -DirDeskSnapshotDir /tmp/snap \
    -DirDeskSnapshotFolder ~/DirDeskFixtures/01-排序与日期 -DirDeskSnapshotAction selectFirst
```

`menuDump:<项目名|项目名…>` 选中这些项目后把右键菜单（不给项目名则为空白处菜单）按层级写入 `<目录>/menu.txt`，含快捷键与"(disabled)"标记，用来与参考库 `04-右键菜单` 的 AX 树比对；`menuDumpLayout:<布局>|<项目名>` 先切换窗格布局再导出。

Wumi 只允许单实例。Wumi 正在使用时，离屏截图、菜单导出和应用内自测都用改了 bundle ID 的副本隐藏运行，不影响正在用的窗口和会话：

```sh
cp -R build/Wumi.app /tmp/h/DirDeskMenuHarness.app
/usr/libexec/PlistBuddy -c "Set :CFBundleIdentifier com.kbwumin13.dirdesk.menuharness" /tmp/h/DirDeskMenuHarness.app/Contents/Info.plist
codesign --force --sign - /tmp/h/DirDeskMenuHarness.app
open -g -j -n --env HOME=/tmp/h/home -a /tmp/h/DirDeskMenuHarness.app --args -DirDeskSnapshotDir /tmp/h/out \
    -DirDeskSnapshotHidden YES -DirDeskApplicationSupport /tmp/h/support \
    -DirDeskSnapshotFolder ~/DirDeskFixtures/01-排序与日期 -DirDeskSnapshotAction "menuDump:a.txt"
```

- `-DirDeskSnapshotHidden YES`：配合 `open -j` 隐藏启动；App 不会主动激活自己，截图时把未上屏的窗口也渲染出来，也不启动闪电搜索索引（副本没有完全磁盘访问，爬取会让系统替副本询问桌面、文稿、下载的访问权限）。
- `-DirDeskApplicationSupport <目录>`：会话、命名工作区、中转舱与闪电搜索快照写到这里。非沙盒 App 的 Application Support 按账户家目录解析，不认 `HOME` 环境变量，不加这个参数时副本会把会话写进真实的 `~/Library/Application Support/DirDesk`。

用完后退出副本，删除 `~/Library/Preferences/com.kbwumin13.dirdesk.menuharness.plist`（偏好同样按 bundle ID 写在真实家目录下），再删掉 `/tmp/h`。`scripts/review/harness.sh` 把这几步包成一条命令，同目录还有逐像素测量用的小脚本（见 `scripts/review/README.md`）。

## 本地化

界面文案以英文为键，简体中文表 `scripts/l10n/zh_hans.py` 是"在用键"的基准；其余语言（`zh_hant`、`ja`、`ko`、`fr`、`de`、`es`、`it`、`pt_br`）各有一个同结构的表，语言列表在 `scripts/l10n/languages.py`。新增或修改 `L("…")` 后：

Wumi 品牌文案的英文键与译文要同步更新，调用处也要使用新键。重新生成前，先同步 `scripts/l10n/` 各语言源表中的品牌文案，避免把已经改为 Wumi 的资源表覆盖回旧名称。

```sh
python3 -I scripts/l10n/check_strings.py Sources Resources/zh-Hans.lproj/Localizable.strings   # 报告代码里用到但缺翻译的键
python3 -I scripts/l10n/add_strings.py . < pairs.tsv                                          # 追加 英文<TAB>中文 对到 zh_hans.py
python3 -I scripts/l10n/add_translations.py . strings.json                                     # 或者一次写入 9 种语言（JSON：英文键 → {表模块: 译文}）
python3 -I scripts/l10n/check_translations.py .                                               # 其余语言：缺键、格式占位符不一致
python3 -I scripts/l10n/make_strings.py .                                                     # 生成全部 Resources/<语言>.lproj/Localizable.strings
```

经变量传入 `L()` 的键（菜单标题等）登记在 `scripts/l10n/dynamic_keys.txt`。设置 › 通用 › 语言只列出包里有字符串表的语言。

## 目录

- `Sources/DirDeskCore`：无 UI 的核心（模型、配置、目录加载与监视、排序分组、文件操作引擎、归档、校验和、模板、文件夹工具）
- `Sources/DirDesk`：App（AppKit 生命周期与主菜单、SwiftUI 外框、NSTableView/NSCollectionView 文件视图、设置）
- `scripts/review`：界面对照用的隐藏副本脚本与测量工具
- `Sources/CArchive`：系统 libarchive 的 API 声明
- `docs/assets`：GitHub 产品介绍使用的原创视觉与真实演示截图

内部验收记录与功能对照资料只保存在本地，不是构建依赖。
