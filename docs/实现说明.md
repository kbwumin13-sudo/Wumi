# Wumi 实现说明

Wumi 使用 Swift、AppKit 与 SwiftUI 构建。内部模块继续使用 DirDesk 名称，以保持 Bundle ID、偏好、会话和索引兼容。构建与运行入口见 [构建与运行](构建与运行.md)。

## 模块与系统接口

| 模块 | 责任 |
| --- | --- |
| `DirDesk` | AppKit 生命周期与窗口、SwiftUI 外框与设置、文件列表与图标视图、检查器和各类操作面板、桌面窗口与全局搜索面板 |
| `DirDeskCore` | 配置模型、目录读取与监视、排序分组、文件操作与撤销、归档、Git、批量重命名、PDF/图片工具、文件夹同步、暂存、桌面布局与搜索索引宿主 |
| `MijiCore`（`Vendor/Miji`） | 内嵌的觅迹索引核心：扫描与 FSEvents 增量更新、SQLite 元数据与 FTS5 正文索引、名称与拼音匹配；正文和 OCR 由按需启动的 `miji-extract` helper 提取 |
| `CArchive` | 系统 libarchive 的 C 接口声明，通过系统库链接，无独立第三方二进制 |

SwiftPM 管理工程，`scripts/build-app.sh` 组装 `.app`、嵌入 `miji-extract` helper、复制本地化和许可、生成图标并签名。默认 Release；部署目标为 macOS 15。文件列表采用 NSTableView，图标和画廊使用 AppKit 视图，SwiftUI 负责窗口辅助区域与设置。图标由 `scripts/make_icon.swift` 绘制。

## 工作区与浏览

窗口包含标签页，标签页持有布局和多个窗格。每个窗格独立保存目录、历史、视图配置、排序分组与选择状态；工作区可命名保存。目录加载、排序派生、图标与 Git 查询在后台完成，结果交回界面时检查请求是否仍有效。没有消费者的过期任务会取消。

目录内容变化通过现有文件系统监听更新。文件状态、iCloud 状态、选择与检查器分别更新，避免为了徽标刷新而重载整张表。四种视图共用文件模型与命令入口。

## 文件操作与大小

复制、移动、重命名、废纸篓与常用整理命令通过操作层执行。撤销与重做先检查缺失、占用和外部修改，出现冲突即停止。压缩与解压使用系统 libarchive；冲突、密码和进度使用原生面板反馈。

普通文件使用逻辑字节大小。文件夹与应用包通过共享后台计算器统计目录内容，包含隐藏文件，不跟随软链接，也不读取文件正文。相同请求会合并，结果在有限缓存中复用；视图、检查器与简介显示相同口径。无法完整读取时显示不可用或已知下界。大树统计需要时间，离开视图后可以取消不再使用的任务。

## 搜索与系统集成

搜索使用内嵌的 MijiCore，Wumi 是唯一的索引宿主：主窗口、全局搜索面板、桌面和文件浮窗共用同一份索引，不需要另外运行觅迹 App。扫描结果写入 SQLite，正文进入 FTS5 索引；文件名和拼音匹配使用直接映射磁盘缓存文件的名称索引，映射后的变化先留在内存，积累过多时重写缓存。索引平时按 FSEvents 路径事件局部更新；系统丢事件或根目录变化时，等上一轮整盘核对完成 30 分钟后再核对，新位置、重新连接和手动重建立即执行。索引任务与提取 helper 以后台优先级运行，使用电池、低电量模式或过热时暂停正文提取和自动整盘核对。搜索面板只在窗口可见时工作。全盘可见范围仍受 macOS 权限约束。

桌面托管用 Wumi 自有的桌面窗口展示系统桌面目录里的真实文件，不复制或移动文件。在 Wumi 中显示、浏览文件夹和打开文件经 `FileOpenRouter` 分派，先在 Wumi 内处理，再交给 Launch Services。

文件系统事件使用 FSEvents，标签查询使用 Spotlight，Git 状态调用系统 `git`，文档与媒体预览使用 macOS 对应框架。PDF、图片处理与校验和工具复用核心服务，不要求另装一套外部运行时。

Wumi 是非沙盒本地应用，按用户的文件系统权限运行；受保护目录按系统隐私机制授权。「设置 → 隐私与权限」提供完全磁盘访问检测与入口。

## 持久化与兼容

- 偏好使用 UserDefaults；配置键保留 `dirdesk-*` 命名，缺失字段按默认值解码。
- 会话保存在 `~/Library/Application Support/DirDesk/WindowSessions/`。同目录体系保存命名工作区、同步配置与历史、文件暂存，以及搜索索引（`Miji/`：SQLite 数据库、名称索引缓存与增量状态）。
- Bundle ID 为 `com.kbwumin13.dirdesk`，可执行文件为 `DirDesk`，对外品牌为 Wumi。
- 测试与截图副本必须使用独立 Bundle ID、偏好域和 `-DirDeskApplicationSupport` 目录。更改 `HOME` 不能替代 macOS 的应用数据隔离。

## 验证与设计

Core 回归测试位于 `Tests/DirDeskCoreTests`，MijiCore 测试位于 `Vendor/Miji/Tests/MijiCoreTests`。应用内自测通过真实窗口控制器覆盖操作、选择、导航、会话与布局；六阶段性能测量方法见 [性能基准](../scripts/performance/README.md)。隐藏截图与测量副本禁止启动全盘索引，测得的短时资源占用不能外推日用含索引的常驻占用。

界面遵循项目 [设计规范](../DESIGN.md)，使用系统语义颜色、原生菜单和键盘操作。源代码、原创视觉与第三方许可随仓库提供；内部对照采集、用户偏好备份、历史构建包和 AI 运行状态不作为构建依赖。
